# Как объяснить проект на защите

Рабочее название: **«Подбор автомобилей по текстовому описанию с учётом пользовательского рейтинга дизайна»**.

## Что решает программа

Пользователь не заполняет множество отдельных фильтров, а пишет фразу. Программа выделяет поддерживаемые признаки и находит подходящие записи. Например, «красивая Toyota до 6 млн» превращается в три условия: бренд Toyota, дизайн не ниже 4, цена не выше 6 000 000 ₽. Дальше результаты сортируются по оценке дизайна.

Называйте реализацию честно: это рекомендательная система со словарным разбором текста и правилами. Код мог быть написан с помощью ИИ, но во время поиска языковая модель не вызывается.

## Алгоритм

1. Привести текст к нижнему регистру, заменить «ё» на «е».
2. Проверить отрицания, которые текущая версия не умеет обрабатывать.
3. Найти бюджет, включая диапазоны и единицы «тысяч» / «млн».
4. Выделить марки, страны, кузова, модели и описательные слова по границам слов.
5. Сформировать план поиска. Если остались непонятные слова, показать их и попросить уточнение.
6. Прочитать каталог и агрегированные оценки из SQLite, применить все ограничения.
7. Отсортировать, отобразить карточки и распознанные критерии.

Новая запись в таблице оценок немедленно влияет на средний балл и последующие запросы. Порог для «красивой» модели равен 4. При равенстве баллов выше запись с большим числом голосов, затем дешевле.

## Основные функции: полные сигнатуры

### `parse_query(query, cars)`

Разбирает запрос и возвращает объект `SearchPlan`.

- `query` — строка пользователя. Обязательный параметр, значения по умолчанию нет.
- `cars` — список словарей каталога; нужен, чтобы распознавать названия моделей. Обязательный параметр, значения по умолчанию нет.

Возвращаемый `SearchPlan` имеет поля:

- `filters` — словарь ограничений, по умолчанию новый пустой словарь: `brands`, `models`, `countries`, `bodies` — списки допустимых значений; `fuel` — тип топлива; `min_price` / `max_price` — числа рублей; `family` / `city` — логические ограничения по кузову. Отсутствие ключа означает отсутствие такого ограничения.
- `labels` — новый пустой список по умолчанию; человекочитаемые подписи условий.
- `unknown` — новый пустой список по умолчанию; оставшиеся неизвестные слова.
- `warnings` — новый пустой список по умолчанию; сообщения об ограничениях и ошибках запроса.
- `beauty`, `power`, `affordable` — логические поля, каждое по умолчанию `False`; включают правила дизайна, мощности и приоритет недорогих моделей.

Например, для текущей задачи `parse_query('красивая Toyota', cars)` вернёт `filters['brands'] == ['toyota']` и `beauty == True`.

### `select_cars(cars, plan, sort='default')`

Возвращает отфильтрованный и отсортированный список автомобилей.

- `cars` — список словарей. Обязательный параметр, значения по умолчанию нет. Каждый словарь содержит `id`, `brand`, `model`, `country`, `body_type`, `engine_power`, `engine_volume`, `price`, `fuel_type`, `demo_design_score`, `design_score`, `votes`. `design_score` — действующий средний или демонстрационный балл, `votes` — число пользовательских оценок; остальные свойства описывают запись каталога.
- `plan` — результат `parse_query`. Обязательный параметр, значения по умолчанию нет.
- `sort` — строковый код сортировки. По умолчанию `'default'`: учитывать контекст запроса, а без приоритета сохранять порядок ID. Другие значения: `'price_asc'`, `'power_desc'`, `'design_desc'`.

Например, `select_cars(cars, plan, sort='price_asc')` сохранит условия «красивая Toyota», но расположит подходящие машины по возрастанию цены. При `unknown` или `warnings` выдача пустая, чтобы не выдавать нерелевантный каталог за ответ.

### `create_app(test_config=None)`

Создаёт и возвращает приложение Flask, настраивает хранилище и регистрирует страницы.

- `test_config` — словарь переопределений конфигурации или `None` (по умолчанию). В обычном запуске `None`; в тестах передаётся временный путь `DATABASE`, тестовый `SECRET_KEY` и `TESTING=True`, чтобы не затрагивать рабочие голоса.

## Схема БД

`cars`: ID, марка, модель, страна бренда, кузов, мощность, объём, демонстрационная оценка, цена, топливо.

`ratings`: `car_id` — ссылка на автомобиль, `voter` — случайный идентификатор браузерной сессии, `score` — целая оценка от 1 до 5. Пара `(car_id, voter)` уникальна, поэтому повторная оценка обновляет предыдущую.

Избранное хранится в подписанной cookie. Подпись защищает от изменения содержимого, но не шифрует его: секретные данные туда не записываются. Формы изменения избранного и рейтинга используют POST и проверку CSRF-токена — случайной строки, связанной с сессией, чтобы другой сайт не мог незаметно отправить такую форму.

## Сценарий демонстрации

1. Открыть каталог и выполнить «недорогая машина»: убедиться, что цены не выше 1,5 млн.
2. Выполнить «красивая Toyota»: показать только Toyota с оценкой от 4.
3. Изменить сортировку: запрос должен сохраниться.
4. Выполнить «кроссовер до 3 млн»: объяснить два ограничения.
5. Открыть модель, сохранить в избранное и поставить оценку. Поменять её: число голосов не должно увеличиться от повторной оценки в том же браузере.
6. Показать неизвестный запрос и честную подсказку вместо случайной выдачи.
7. Показать тесты и объяснить ограничение учебных данных.

## Чего нельзя обещать

Не заявляйте понимание любых фраз, актуальность цен, объективную красоту или защиту опроса от накрутки. Для развития проекта нужны подтверждённые данные с годами и комплектациями, фотографии с правом использования, реальный опрос с описанной выборкой, больше языковых конструкций и отдельное тестирование качества поиска. Сейчас проект демонстрирует работающий алгоритм и полный цикл от фразы до объяснимой рекомендации.
